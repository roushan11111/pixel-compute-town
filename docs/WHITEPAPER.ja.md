## 要旨（Abstract）

生成AIの急速な普及により、世界中の開発者コミュニティは相互に増幅し合う3つの構造的課題に直面しています。第一に、毎月リセットされる大量の余剰APIクレジットや月次・週次AI CLIサブスクリプション枠が無駄に消滅しています。第二に、AIによる爆速実装が可能になった結果、独創的なプロダクトのアイデアが公開直後に模倣・蒸留され、「最初にアイデアを生み出した人物」が正当に記録・還元されにくくなっています。第三に、低品質なAI生成コード（AI Slop）や自動化されたマイクロPRの乱発により、本質的な設計や重要バグ修正を担うコア開発者の貢献が希薄化しています。

**PixelCompute Town（ピクセル算力タウン）**は、**デュアルトラック準拠計算モデル（Zero-Trust BYOK + BYOT）**、**SHA-256 暗号学的アイデア帰属チェーン（Proof of First Spark）**、**5% / 85% / 10% 成果連動型分配と 70/30 希薄化防止バケット数理モデル**、および**4層アンチスロップ・ガバナンス**を統合したオープンソース協業プロトコルです。親しみやすい 32×32 HD ピクセルアートとオリジナル 8-bit 音楽で参加障壁を下げつつ、決済には**1:1 米ドル連動ステーブルコイン（USDC / USDT）＋法定通貨（Polar / Stripe）＋引き換えコード**のみを採用し、投機的な独自トークンを一切発行せず、余剰AI計算資源を検証済み・収益化可能なプロダクトへと昇華させます。

## 1. AI経済における3つの構造的課題

1. **毎月リセットされる余剰計算資源の損失**：API無料枠・クラウドクレジットや Gemini CLI / Claude Code / Codex CLI / Cursor の定額枠の多くが未消化のまま失効する一方、非公式なアカウント共有プロキシは利用規約（ToS）違反とアカウント停止リスクを伴います。
2. **オリジナルアイデアの即時コピーと蒸留**：AI時代には優れた着想が数時間で模倣されるため、改ざん不可能な発案タイムスタンプ証明とコピー防止機構が不可欠です。同時に、手を動かさない発案者が過大な割合を独占すると実働エンジニアが集まりません。
3. **低品質 AI Slop によるコア貢献者の希薄化**：コミット数やトークン消費量に応じた報酬設計では、大量の冗長コードや無意味な修正を投下するボットがコア開発者の取り分を奪ってしまいます。

## 2. デュアルトラック準拠アーキテクチャ：Zero-Trust BYOK & BYOT

PixelCompute Town は**「ユーザーの秘密認証情報に一切触れず、AIベンダーの利用規約を厳守する」**ことを最優先原則とします。

- **Track A：オートファクトリー（Zero-Trust BYOK / `api_auto`）**
  - 多言語JSON翻訳、ユニットテスト作成、ドキュメント整備などの並列微タスク向け。
  - 推論リクエストはユーザーのブラウザから直接 Gemini API / OpenAI 互換エンドポイント / ローカル Ollama へ送信され、APIキーはブラウザの `localStorage` のみに保存されます（サーバーへは一切送信しません）。
- **Track B：ギルド懸賞（Compliant BYOT / `guild_bounty`）**
  - コア機能PR、アーキテクチャ設計、難関バグ修正向け。
  - ゼロ依存のオープンソースCLI `bin/pixel-worker.mjs` を通じて、ユーザー自身の正規ローカルツール（Gemini CLI / Claude Code / Codex CLI 等）で作業し、人間が確認した上でPRを提出します。`pixel-worker onboard` は 15 分間有効なデバイスコード（`PCT-XXXX-XX`）を発行し、`/onboard` 画面で明示的に権限を承認して連携します。

## 3. Proof of First Spark（POFS）：暗号学的アイデア帰属証明

`src/server/provenance.mjs` に実装された **`PCT-POFS-v1`** により、すべての新規アイデア提案は改ざん検知可能な **SHA-256 ハッシュチェーン** に記録されます。

```text
C_i = JSON.stringify({
  protocol: "PCT-POFS-v1",
  name, tagline, description,
  originatorId, originatedAt,
  prevIdeaHash: H_{i-1}
})
H_i = SHA-256_hex(UTF-8(C_i))
```

- **日英中対応コピーキャット検知**：Unicode NFKC 正規化＋英単語＆CJK 2-gram の最大 Jaccard 類似度を算出し、類似度 `>= 0.40` で警告、`>= 0.65` で重複提案を HTTP **`409 POTENTIAL_COPYCAT`** としてブロックし、原案への共同参加（`POST /api/projects/:id/join`）を案内します。
- **ログイン不要の公開検証ページ**：`GET /verify/:hash` で誰でも原案者・UTCタイムスタンプ・64文字SHA-256指紋を検証でき、900×520 ピクセル風《アイデア初出証明書 PNG》もダウンロード可能です。

## 4. 5% / 85% / 10% 成果分配と 70/30 希薄化防止数理モデル

### 4.1 3プール分配（5% / 85% / 10%）
プロジェクト公開後の総売上 `R`（USD）は以下の通り厳密に配分されます：
- **5% 初出アイデア永続ロイヤリティ（`R_spark`）**：発案者（`originatorId`）へ無条件・永続的に帰属。
- **85% 実働ビルダー成果プール（`R_merit`）**：PoAW 検証済み貢献ポイントに基づき 70/30 バケットルールで配分（発案者が実装にも参加した場合は 5% に加えて成果分も重複受領）。
- **10% プラットフォーム運営・公証キャリー（`R_platform`）**：インフラ維持・検証基盤・決済処理に充当。

### 4.2 70/30 希薄化防止バケット不変式
85% 成果プール内は2つの排他的バケットに分離されます：
- **🔥 コア実働バケット（`core`・上限 70%＝総売上の 59.5%）**：ギルド懸賞、コア機能PR、アーキテクチャ、バグ修正、ピアレビュー報酬。
- **⚙️ 周辺微タスクバケット（`peripheral`・上限 30%＝総売上の 25.5%）**：翻訳、ドキュメント、テスト、素材仕様。

## 5. 4層アンチスロップ・ガバナンス（Anti-Slop 4-Layer Moat）

1. **第1層・固定ポイント制＆自動検証（`verifier.mjs`）**：行数・トークン消費ではなく採用タスクの固定ポイントのみを付与。低多様性・重複スロップ・不正JSONを自動排除。
2. **第2層・AIブラインド診断（`runAiBlindReview`）**：Diff量・水増し率（`bloatRatioPct`）・空関数・過剰コメントを自動採点しリスク警告を付与。
3. **第3層・実働レビュアー承認キュー（`canUserReview`）**：プロジェクトの実績ある貢献者・発案者・管理者のみが承認・却下可能。優良PR承認でレビュアーに **`+15G` ＋ `+5` コアポイント** を付与。
4. **第4層・ステーキング没収＆クールダウン処罰**：コア懸賞受注時に **`25G–30G`** の誠意デポジットを凍結。承認で全額返還、悪質なAIスロップ却下時は**デポジット全額をレビュアーへ報奨として没収**し、信用度 `-5`・連続2回で HTTP **`429 WORKER_COOLDOWN`** 受注停止。
