## 摘要（Abstract）

在生成式 AI 全面普及的當下，全球開發者社群正同時面臨三個看似獨立、實則彼此強化的結構性失衡：第一，數千萬名開發者每個月都有大量「月底歸零」的閒置 API 贈金與 AI CLI 月／週訂閱額度白白蒸發；第二，在 AI 極速實作能力下，原創產品構想極易被瞬間複製、改頭換面或低質蒸餾，導致「首位提出好點子的人」難以被公平紀錄與回饋；第三，開源協作正遭受低成本垃圾 AI（AI Slop）與自動化微任務刷單的劇烈衝擊，真正扛起架構設計與關鍵 Bug 修復的核心工程師反而面臨貢獻稀釋與審閱過勞。

**PixelCompute Town（像素算力鎮）** 提出一套結合 **雙軌合規算力協作（Zero-Trust BYOK + BYOT）**、**密碼學創意首發溯源鏈（Proof of First Spark）**、**5% / 85% / 10% 多勞多得動態分紅與 70/30 防稀釋分桶數學模型**、以及 **4 層防垃圾 AI 治理體系** 的開源協作協議。本協議透過像素風經營遊戲化介面降低協作門檻，在結算層嚴格採用 **1:1 法幣錨定穩定幣（USDC / USDT）＋傳統法幣結帳（Polar / Stripe）＋兌換碼**，堅持不發行任何投機代幣，將全球零散閒置算力精準匯聚為可驗收、可持續變現的高品質開源與獨立產品。

## 1. 時代痛點：AI 經濟的三重結構性失衡

### 1.1 每月歸零的閒置算力黑洞

AI 基礎設施的計費模式正分化為「按量 API 贈金／免費配額」與「固定月／週費率的官方 CLI／IDE 訂閱（如 Gemini CLI、Claude Code、Codex CLI、Cursor）」。多數開發者在平峰期僅消耗不到 30%–50% 的可用額度，剩餘配額在結算週期結束後立即歸零。另一方面，市面上試圖「回收」閒置額度的黑灰產共享反代池，往往透過非法收集用戶 Cookie、OAuth Token 或轉售 API Key 運作，不僅嚴重侵害隱私，更直接違反主流 AI 廠商的服務條款（ToS），導致開發者帳號遭永久封禁。

### 1.2 原創點子被低成本複製與「蒸餾」

在傳統軟體工程時期，從構想到最小可行產品（MVP）需要數月人力，因此點子本身較難被瞬間掠奪；然而在 AI 輔助編程時代，一個精準切中痛點的創意只需公開片刻，便可能被他人用 AI 批量複製、微調包裝並搶先發布。若協作平臺無法提供不可竄改的首發時間戳公證與反抄襲攔截機制，原創發起人將失去分享靈感的動機；反之，若平臺過度向「只提想法不動手」的發起人傾斜（例如讓發起人拿走 50% 以上永久份額），又會嚇跑真正投入時間與算力把產品落地交付的實幹工程師。

### 1.3 垃圾 AI（AI Slop）稀釋開源實幹者

開源維護者近年普遍遭遇「低品質 AI PR 洪水」：自動化腳本使用極低成本模型大量提交無意義的 README 改字、重複註解、空函式佔位或冗長灌水 Diff。在傳統「按提交次數」或「按消耗 Token 數」計酬的激勵模型中，這類垃圾產出不僅浪費維護者的審閱精力，更會嚴重稀釋核心開發者的貢獻權重，造成「劣幣驅逐良幣」的系統性崩壞。

## 2. 雙軌合規架構：Zero-Trust BYOK 與 BYOT 協議

PixelCompute Town 的第一條建築紅線是 **「絕對不碰用戶私密憑證，絕對遵守 AI 廠商服務條款」**。系統將所有開發工作依風險與算力特性切分為兩條完全隔離的軌道：

```text
┌────────────────────────────────────────────────────────────────────────────┐
│            PixelCompute Town Protocol Engine (Zero-Dep Node.js)            │
│   Proof of First Spark · PoAW Verifier · 70/30 Governance · SQLite WAL     │
└──────────────────▲──────────────────────────────────────▲──────────────────┘
                   │ 僅回傳結構化交付物與驗收分數             │ 僅回傳進度心跳與用戶親自確認之 PR/成果
                   │ （後端永不接觸 API Key）                │ （本機憑證永不出境）
┌──────────────────┴──────────────────┐  ┌────────────────┴──────────────────┐
│  Track A：自動工坊 (Zero-Trust BYOK) │  │  Track B：懸賞工會 (Compliant BYOT) │
│  • 瀏覽器直連 Gemini / OpenAI 相容端點 │  │  • 本機零依賴 CLI：pixel-worker v0.4 │
│  • 支援本地 Ollama (localhost 免 Key)│  │  • OAuth Device Flow (/onboard) 核准 │
│  • Key 僅存 localStorage + Token 上限│  │  • 本機跑 Gemini/Claude/Codex 官方 CLI│
│  • 對應週邊微任務池 (≤30% 封頂)        │  │  • 對應核心實幹池 (70% 數學保護)       │
└─────────────────────────────────────┘  └───────────────────────────────────┘
```

### 2.1 Zero-Trust BYOK（Bring Your Own Key）
- 適用軌道：**自動工坊 (`api_auto`)**。
- 所有推論請求直接由用戶端瀏覽器發往目標模型端點（Google `generativelanguage.googleapis.com`、OpenRouter、DeepSeek 或本機 `http://localhost:11434/v1`）。
- API Key 僅儲存於瀏覽器端 `localStorage`（鍵名 `pixel_compute_town_byok_v1`），任何 HTTP API 請求都不會夾帶用戶金鑰回傳至平臺伺服器。
- 內建單次任務最大輸出 Token 上限（預設 `2,048`，可調 `256`–`16,384`）與每日小人 Token 體力軟上限，避免自動化掛機失控超支。

### 2.2 Compliant BYOT（Bring Your Own Tool）與 Device Flow 核准
- 適用軌道：**懸賞工會 (`guild_bounty`)**。
- 針對月／週訂閱工具，平臺提供單一零依賴本機橋接器 `bin/pixel-worker.mjs`（約 1,180 行純 Node.js 原始碼，公開可稽核）。
- **嚴格隔離邊界**：`pixel-worker` 不讀取 `~/.gemini`、`~/.claude`、`~/.codex` 或任何瀏覽器 Cookie，僅在用戶本機透過 `child_process` 呼叫用戶自己核准的官方 CLI 指令，並於提交前由開發者親自確認。
- **裝置註冊與嚴格審核**：執行 `pixel-worker onboard` 會產生 15 分鐘有效之裝置授權碼（`PCT-XXXX-XX`）並導向瀏覽器 `/onboard?code=...` 頁，由用戶檢視 4 條零信任權限清單後手動核准；若運營鎮長開啟「嚴格裝置審核模式（`strictDeviceReview`）」，新裝置將進入 `pending_review` 佇列，經人工核准才可正式上線。

## 3. Proof of First Spark（POFS）創意溯源協議

為落實「尊重原創首發、反對抄襲蒸餾」的價值主張，PixelCompute Town 在 `src/server/provenance.mjs` 實作了零依賴密碼學存證協議 **`PCT-POFS-v1`**。

### 3.1 SHA-256 不可竄改創意雜湊鏈

每一筆新提案 $P_i$ 在建立瞬間，系統依序指派單調遞增索引 $i$（`provenanceIndex`）、首發者帳號 ID（`originatorId`）、UTC ISO-8601 時間戳（`originatedAt`）與前一筆創意的指紋 $H_{i-1}$（創世前序雜湊為 64 個 `0`，即 `GENESIS_HASH`）。其不可竄改指紋 $H_i$ 定義如下：

$$
C_i = \text{JSON.stringify}\!\left(\{
  \text{protocol}: \text{"PCT-POFS-v1"},\;
  \text{name},\; \text{tagline},\; \text{description},\;
  \text{originatorId},\; \text{originatedAt},\;
  \text{prevIdeaHash}: H_{i-1}
\}\right)
$$

$$
H_i = \text{SHA-256}_{\text{hex}}\!\left(\text{UTF-8}(C_i)\right) \in \{0\text{–}9, a\text{–}f\}^{64}
$$

任何對歷史項目名稱、簡介、首發者或時間戳的篡改，都會導致該區塊及所有後續區塊的 `verifyProvenanceChain()` 驗證失敗（`valid === false`），且平臺啟動載入時絕不自動覆寫既有 `ideaHash`，完整保留防篡改稽核能力。

### 3.2 中英雙語反抄襲演算法

為防範中英文混合改寫、跨欄位貼上或省略簡介來規避查重，系統採用 **NFKC 正規化 ＋ 雙語特徵切分 ＋ 多維度最大 Jaccard 相似度**：

1. **雙語特徵集 $T(s)$**：
   - 英文／數字詞元：擷取小寫 `[a-z0-9]+` 標記為 `en:<word>`。
   - 中日韓（CJK）字元序列：長度 $\ge 2$ 時提取所有相鄰 **2-gram** 標記為 `zh:<c_k c_{k+1}>`（單字則標記 `zh:<c>`）。
2. **Jaccard 相似度**：
   $$
   J(A, B) = \frac{|T(A) \cap T(B)|}{|T(A) \cup T(B)|} \in [0, 1]
   $$
3. **跨欄位防稀釋取最大值**：對候選提案與每筆既有原創分別計算名稱相似度 $s_{\text{name}}$、副標相似度 $s_{\text{tagline}}$、簡介相似度 $s_{\text{desc}}$、對齊欄位合併相似度 $s_{\text{matched}}$ 與全欄位合併相似度 $s_{\text{all}}$，取：
   $$
   S_{\text{final}} = \max(s_{\text{name}},\, s_{\text{tagline}},\, s_{\text{desc}},\, s_{\text{matched}},\, s_{\text{all}})
   $$
4. **雙門檻治理動作**：
   - **警示門檻（$S_{\text{final}} \ge 0.40$，`COPYCAT_WARN_THRESHOLD`）**：前端即時彈出相似創意警示，要求創作者確認差異化並標記致敬來源指紋（`inspiredByHash`）。
   - **攔截門檻（$S_{\text{final}} \ge 0.65$，`COPYCAT_HIGH_THRESHOLD`）**：後端硬性拒絕建立重複提案，回傳 HTTP **`409 POTENTIAL_COPYCAT`**，附上原創首發者、時間戳與 `ideaHash`，並引導呼叫 `POST /api/projects/:id/join` 直接加入原創意共建。

### 3.3 無門檻公開查驗與憑證輸出

- **公開 API**：`GET /api/provenance/chain`（逐筆重算整條雜湊鏈）與 `GET /api/provenance/verify/:hash`（支援完整 64 碼或 8+ 碼前綴）。
- **公開 SSR 查驗頁**：任何人免登入造訪 `GET /verify/:hash`，通過即亮出 **`✅ VERIFIED ON PIXELCOMPUTE PROVENANCE CHAIN`** 官方印章；偽造或篡改回傳 HTTP `404` 紅牌警告。
- **像素公證證書**：前端可即時繪製並下載 900×520《創意首發溯源證書 PNG》，內嵌首發者、UTC 時間戳與 64 碼指紋供外部社群與版權歸檔。

## 4. 5% / 85% / 10% 動態分紅與 70/30 防稀釋數學模型

PixelCompute Town 的分配哲學可濃縮為一句話：**「尊重踏出 0 到 1 的創意火花，但絕不讓空想獨佔；讓真正把產品交付上線的實幹者拿走最大頭，且用數學鎖死防稀釋護城河。」**

### 4.1 頂層三池分配公式（5% / 85% / 10%）

設某已上線項目在結算週期獲得總營收 $R > 0$（單位：USD），系統將其精確劃分為三個獨立資金池：

$$
R_{\text{spark}} = \text{round}_2(0.05 \times R), \quad
R_{\text{platform}} = \text{round}_2(0.10 \times R), \quad
R_{\text{merit}} = \text{round}_2(R - R_{\text{spark}} - R_{\text{platform}}) = 0.85 \times R
$$

- **$R_{\text{spark}}$（5% 首發創意永久版稅）**：無條件、永久歸屬鏈上記錄的 `originatorId`。
- **$R_{\text{merit}}$（85% 實幹建設多勞多得池）**：依 70/30 分桶隔離規則分配給所有通過 PoAW 驗收的實幹貢獻者。若發起人親自參與實作，其領取金額為 $R_{\text{spark}}$ 與實幹池所得的**直接疊加**。
- **$R_{\text{platform}}$（10% 平臺公證運營 Carry）**：歸入平臺維護溯源公證、驗收審閱引擎與支付清算基礎設施。

### 4.2 85% 實幹池內部：70/30 分桶隔離數學證明

為防堵廉價 AI 狂刷週邊微任務稀釋核心開發者，系統在 `src/server/governance.mjs` 將每筆驗收通過的貢獻點數嚴格歸入兩個互斥分桶：

- **🔥 核心實幹桶（$\mathcal{C}$ / `core`）**：涵蓋工會懸賞大單、`feature_pr`、`architecture`、`bugfix` 以及實幹審閱人的 `+5` 核心審閱獎勵點。配額上限 $\alpha = 0.70$（佔總營收 $59.5\%$）。
- **⚙️ 週邊微任務桶（$\mathcal{P}$ / `peripheral`）**：涵蓋 API 軌道微任務、`i18n`、`docs`、`pixel_spec`、`unit_test`、`qa_audit`。配額上限 $\beta = 0.30$（佔總營收 $25.5\%$）。

設全體參與者在核心桶的總點數為 $C_{\text{total}} = \sum_{u} c_u$，在週邊桶的總點數為 $P_{\text{total}} = \sum_{u} p_u$，則雙桶實際分紅池 $(M_{\text{core}}, M_{\text{periph}})$ 定義為：

$$
(M_{\text{core}},\, M_{\text{periph}}) =
\begin{cases}
\bigl(\text{round}_2(0.70 \cdot R_{\text{merit}}),\; \text{round}_2(R_{\text{merit}} - M_{\text{core}})\bigr) & \text{若 } C_{\text{total}} > 0 \text{ 且 } P_{\text{total}} > 0 \\[6pt]
(R_{\text{merit}},\; 0) & \text{若 } C_{\text{total}} > 0 \text{ 且 } P_{\text{total}} = 0 \\[6pt]
(0,\; R_{\text{merit}}) & \text{若 } C_{\text{total}} = 0 \text{ 且 } P_{\text{total}} > 0
\end{cases}
$$

對任意貢獻者 $u$，其最終分紅總額 $D_u$ 為：

$$
D_u = \mathbb{I}(u = \text{originator}) \cdot R_{\text{spark}}
    + M_{\text{core}} \cdot \frac{c_u}{C_{\text{total}}}
    + M_{\text{periph}} \cdot \frac{p_u}{P_{\text{total}}}
$$

（若任一分桶總點為 0 則該項為 0；最後執行分幣湊整守衛 `cent reconciliation guard`，確保 $\sum_u D_u + R_{\text{platform}} \equiv R$ 精確至 `$0.01`，零浮點殘差。）

**防稀釋不變式（Anti-Dilution Invariant）**：只要 $C_{\text{total}} > 0$，無論週邊桶總點數 $P_{\text{total}} \to \infty$，核心實幹者 $u$ 的核心池收益下界永遠鎖死：

$$
\lim_{P_{\text{total}} \to \infty} \left( M_{\text{core}} \cdot \frac{c_u}{C_{\text{total}}} \right) = 0.595 \cdot R \cdot \frac{c_u}{C_{\text{total}}}
$$

## 5. 4 層防垃圾 AI 治理體系（Anti-Slop 4-Layer Moat）

除了數學上的 70/30 分桶，PixelCompute Town 在任務全生命週期建立 4 道串聯防線，讓製造垃圾 AI 提交的**期望報酬恆為負值**：

### Layer 1：任務定額 ＋ 70/30 分桶隔離 ＋ PoAW 機器硬門檻
- 每張任務的貢獻點數皆為固定定額（而非按字數或 Token 計算），徹底斷絕「寫越長領越多」的動機。
- 所有提交先通過 `src/server/verifier.mjs` 的三項硬校驗：最小實質長度門檻、AI Slop 反灌水偵測（封鎖重複字元、英文詞彙多樣性 `< 22%`、中文 2-gram 多樣性 `< 28%`、多行複製貼上 `< 35%`、佔位符關鍵字）、以及依任務類別檢查合法 JSON／程式碼特徵／GitHub PR 格式。

### Layer 2：跨模型 AI 盲審體檢（`runAiBlindReview`）
- 進入審閱佇列的提交立即接受自動化盲審診斷，解析 Unified Diff 或程式碼本文，產出：
  - `diffLinesAdded` / `diffLinesRemoved`
  - **注水比 `bloatRatioPct`（0–100%）**：綜合懲罰重複行率（`>= 35%` 觸發 `DUPLICATE_LINES`）、過高註解佔比（`>= 45%` 觸發 `EXCESSIVE_COMMENTS`）、空函式佔位符（`>= 2` 個觸發 `EMPTY_STUB_FUNCTIONS`）、佔位註解（`TODO/FIXME/placeholder` 觸發 `FILLER_PLACEHOLDERS`）及異常純新增大 Diff（`+500/-0` 觸發 `OVERSIZED_ADD_ONLY_DIFF`）。
  - **盲審分數 `aiScore`（5–99）** 與三級風險燈號：**`low`（綠）**、**`medium`（黃，`aiScore < 75` 或 `bloat >= 25%`）**、**`high`（紅，`aiScore < 50` 或 `bloat >= 55%` 或 `>= 2` 項異常旗標）**。

### Layer 3：雙階段實幹審閱團與合併否決權
- 支援開發者主動勾選送審，或由鎮長開啟全局強制雙階段實幹審閱（`settings.peerReviewRequired = true`）。
- **資格鎖定（`canUserReview`）**：僅限創始鎮長、該項目首發者與在該項目已通過驗收的實幹貢獻者具備裁決權；無關新帳號回傳 HTTP `403 REVIEWER_NOT_ELIGIBLE`。
- **正向審閱激勵**：批准優質 PR，審閱人實得 **`+15G` 金幣 ＋ `+5` 核心池貢獻點 ＋ 信譽 `+1`**，讓高品質 Code Review 本身成為有分紅權重的核心貢獻。

### Layer 4：誠意押金沒收 ＋ 信譽門檻 ＋ 垃圾冷卻懲罰
- **信譽門檻**：承接工會核心大單預設須達 **信譽分 ≥ 60**（不足攔截 HTTP `403 REPUTATION_TOO_LOW`）。
- **誠意押金（Stake Gold）**：領取工會大單凍結 **`25G`**（高價現金懸賞 ≥ `$25` 凍結 **`30G`**）。通過驗收或主動 `release` 則 **100% 退還**；一旦被實幹審閱團駁回，**全額押金立即沒收並直接賠付給該名審閱人**作為抓蟲賞金！
- **累計違規冷卻**：垃圾提交者同時扣除信譽分 **`-5`**；同一算力小人連續累計 **`2` 次垃圾提交（`SLOP_STRIKE_LIMIT = 2`）**，立即鎖定反刷冷卻期（預設 **`60` 秒**，可由 `SLOP_COOLDOWN_SEC` 調整），冷卻期間接單直接回傳 HTTP **`429 WORKER_COOLDOWN`**。

| 參與行為 | 提交者結果 | 審閱人結果 | 系統安全效果 |
| :--- | :--- | :--- | :--- |
| **高品質 PR 過審** | 獲核心點數＋退回押金＋90% 懸賞 | 獲 **`+15G` ＋ `+5` 核心點 ＋ 信譽 `+1`** | 雙贏正向飛輪，優質程式碼快速合併 |
| **垃圾 AI 注水遭駁回** | **0 貢獻、信譽 `-5`、押金 `-25G~-30G` 沒收**、連 2 次觸發 `429` 冷卻 | **沒收對方 `25G~30G` 歸自己＋信譽 `+1`** | 垃圾提交者期望收益為負，審閱人有強烈動機抓蟲 |

## 6. 非託管三合一結算與穩定幣微支付基礎設施

### 6.1 為何只用 1:1 USDC / USDT，而絕不發行平臺空氣幣？

大量 Web3 協作專案失敗的根本原因，在於發行缺乏真實需求支撐的原生波動代幣（空氣幣），導致專案從「做產品」淪為「炒幣與倒貨」，真實工程師因幣價腰斬而離場。PixelCompute Town 明確宣示 **Zero Native Token Policy（零原生代幣原則）**：

1. **計價與結算錨定真實購買力**：所有懸賞、廣告位、Pro 訂閱與項目分紅均以 **USD** 計價，鏈上只接受全球流通、1:1 美元儲備錨定的 **USDC 與 USDT**。
2. **多鏈低 Gas 微支付**：原生支援 **Base（推薦，手續費常低於 `$0.01`）**、**Polygon**、**Arbitrum** 與 **Solana**，讓門檻低至 **`$5.00 USD`** 的跨國開發者分紅微支付變得經濟可行，不受傳統銀行跨境電匯 `$25–$40` 高額手續費與地區開戶限制阻礙。
3. **非託管與防重放安全**：平臺不為用戶代管私鑰，僅綁定用戶個人收款地址；所有收款訂單具備 30 分鐘效期與唯一備註碼（`PCT-XXXXXX`），且對鏈上 `TxHash` 進行嚴格格式驗證與全庫防重放去重（重複使用回傳 `409`）。

### 6.2 三合一收付閉環

為了同時覆蓋 Web3 開發者、國際信用卡用戶與華語獨立贊助社群，系統內建三軌並行收付引擎（`src/server/payments.mjs`）：
1. **穩定幣直收與分紅出款**：USDC / USDT 四鏈收付 + 滿 `$5` 提領。
2. **國際法幣結帳**：整合 **Polar.sh**（開源 Merchant of Record，自動處理全球稅務）與 **Stripe**，內建 `HMAC-SHA256` Webhook 簽名驗證（`/api/webhooks/polar`、`/api/webhooks/stripe`）。
3. **卡密兌換碼系統**：支援鎮長批次生成隨機卡密（`PIXEL-PRO-XXXX` 等）上架至 **愛發電 / Ko-fi / Gumroad**，零技術門檻即可完成全球收款。

## 7. 商業模式與法律安全邊界

### 7.1 四大透明且對齊的平臺現金流

平臺本身不靠割韭菜或賣戰力盈利，所有收入皆與開源生態繁榮正相關，並即時揭露於「創作者金庫」透明帳本：

1. **現金懸賞 10% 託管服務費**：項目方充值或發布現金懸賞，實幹貢獻者實得 90%，平臺收取 10% 驗收與託管服務費。
2. **免費孵化項目 10% 公證運營分成（Platform Carry）**：來自 5% / 85% / 10% 協議，只有項目真正做起來並產生真實外部營收時，平臺才隨創作者一同獲利。
3. **像素廣場霓虹廣告位（`$29` / 7 天）**：項目方可租用廣場置頂與畫布霓虹看板曝光，加速招募算力小隊。
4. **外觀皮膚與 Pro 通行證（`$9/月`、創世外觀禮包 `$15`）**：純視覺外觀、金框《算力打工證》與榮譽徽章，**絕不販售投票權、信譽分或任務配額加成**。

### 7.2 法律定性與合規防火牆

PixelCompute Town 在協議設計之初即建立清晰的法律安全邊界：

- **明確定位為「開源勞務懸賞與創作版稅分配協議」**：
  - 貢獻者所得的 **85% 實幹池分紅**，嚴格對應其本人主動交付並通過驗收的技術勞務成果（Proof of Accepted Work），屬於開源貢獻報酬與合作開發利潤分成，**並非被動投資回報**。
  - 首發者所得的 **5% 版稅**，屬於原創作品構想授權之商業版稅（Commercial Spark Royalty）。
- **非證券、非集資、非吸儲**：平臺不允許用戶「出錢買份額坐等升值」，不發行任何可自由轉讓交易的股權憑證或投資型代幣（明確區隔美國 Howey Test 之投資契約定義），亦不經營資金池理財或借貸業務。
- **反洗錢與防濫用護欄**：支援鎮長開啟「嚴格裝置人工審核」、強制實幹審閱、IP 速率限制（預設 120 次/分鐘）與 SQLite 稽核日誌留存。
- **AI 廠商條款合規**：透過 Zero-Trust BYOK 與本機官方 CLI BYOT 設計，徹底切割共享帳號與違規轉售風險。
