## Abstract

As generative AI becomes ubiquitous, the global developer ecosystem faces three compounding structural imbalances. First, tens of millions of builders lose unused API grants and fixed-rate monthly or weekly AI CLI quotas every billing cycle when quotas reset to zero. Second, because AI accelerates implementation from months to hours, original product ideas are routinely copied, repackaged, or "distilled" within minutes of publication—leaving the first person who sparked the concept uncredited and unrewarded. Third, open-source repositories are increasingly flooded with low-effort AI Slop and automated micro-PR farming, diluting core engineers who actually design architectures and ship production code.

**PixelCompute Town** introduces an open-source collaboration protocol combining **Dual-Track Compliant Compute (Zero-Trust BYOK + BYOT)**, a **SHA-256 Idea Provenance Chain (`Proof of First Spark`)**, a **5% / 85% / 10% Dynamic Merit Split with a 70/30 Anti-Dilution Bucket Invariant**, and a **4-Layer Anti-Slop Governance System**. Wrapped in a cozy 32×32 HD pixel-art town interface with original 8-bit music, PixelCompute Town settles global bounties and creator royalties strictly in **1:1 USD-pegged stablecoins (USDC / USDT)** alongside **Polar / Stripe fiat checkout and redeem codes**—with zero native speculative tokens—turning wasted global compute into verifiable, revenue-generating software.

## 1. The Triple Structural Imbalance of the AI Economy

### 1.1 The Resetting Idle Quota Black Hole

Modern AI billing has split into usage-based API credits/grants and fixed-rate monthly or weekly CLI/IDE subscriptions (such as Gemini CLI, Claude Code, Codex CLI, and Cursor). During normal workweeks, most developers consume only 30%–50% of their allocated quotas before reset. Meanwhile, gray-market "quota pooling" proxies harvest user cookies, OAuth tokens, or shared API keys—violating provider Terms of Service (ToS), exposing private data, and triggering permanent account bans.

### 1.2 Instant Idea Copying and Distillation

When building an MVP took six months, sharing an idea carried low immediate theft risk. In the AI-native era, a crisp product insight can be cloned and launched by opportunistic copycats before the originator even ships v0.1. Without tamper-evident origination timestamps and anti-copycat enforcement, builders stop sharing ideas publicly. Conversely, granting a passive idea proposer 50%+ permanent ownership drives away the engineers who do the actual work.

### 1.3 AI Slop Dilution of Core Builders

Open-source maintainers now face waves of automated, low-value PRs: cosmetic README edits, bloated comment walls, stub functions, and padded diffs generated by ultra-cheap models. Any incentive system that pays per commit, per line of code, or per token burned inevitably rewards spammers and drives away real architects.

## 2. Dual-Track Compliant Architecture: Zero-Trust BYOK & BYOT

PixelCompute Town enforces one absolute engineering boundary: **the server never touches user API keys, personal subscription credentials, or browser cookies, and strictly respects AI vendor Terms of Service.** Work is separated into two clean tracks:

```text
┌────────────────────────────────────────────────────────────────────────────┐
│            PixelCompute Town Protocol Engine (Zero-Dep Node.js)            │
│   Proof of First Spark · PoAW Verifier · 70/30 Governance · SQLite WAL     │
└──────────────────▲──────────────────────────────────────▲──────────────────┘
                   │ Structured artifacts & PoAW scores   │ Progress heartbeats & human-reviewed PRs
                   │ (Server NEVER receives API Keys)     │ (Local credentials NEVER leave machine)
┌──────────────────┴──────────────────┐  ┌────────────────┴──────────────────┐
│  Track A: Auto Factory (BYOK)       │  │  Track B: Guild Hall (BYOT)       │
│  • Direct browser -> Gemini/OpenAI  │  │  • Zero-dep CLI: pixel-worker v0.4│
│  • Local Ollama support (no key)    │  │  • OAuth Device Flow (/onboard)   │
│  • Key in localStorage + token caps │  │  • Official Gemini/Claude/Codex   │
│  • Maps to Peripheral Pool (<=30%)  │  │  • Maps to Core Merit Pool (70%)  │
└─────────────────────────────────────┘  └───────────────────────────────────┘
```

### 2.1 Zero-Trust BYOK (Bring Your Own Key)
- **Track**: Auto Factory (`api_auto`) for parallelizable, machine-verifiable micro-tasks (i18n JSON translation, unit tests, documentation, pixel specs, QA checks).
- Inference requests go directly from the player's browser to Google Gemini (`generativelanguage.googleapis.com`), OpenAI-compatible endpoints (OpenRouter, DeepSeek), or local Ollama (`http://localhost:11434/v1`).
- API keys stay exclusively in browser `localStorage` (`pixel_compute_town_byok_v1`) and are never transmitted to PixelCompute Town servers.
- Built-in per-task output token caps (default `2,048`, configurable `256`–`16,384`) and daily worker stamina caps prevent runaway spend.

### 2.2 Compliant BYOT (Bring Your Own Tool) & Device Flow Approval
- **Track**: Guild Bounties (`guild_bounty`) for high-value architecture, core features, and bug fixes.
- Players use their own licensed local tools (Gemini CLI, Claude Code, Codex CLI, Cursor, or hand-written code) to solve public open-source bounties and manually review every PR before submission.
- The open-source, zero-dependency bridge `bin/pixel-worker.mjs` never reads `~/.gemini`, `~/.claude`, `~/.codex`, or browser cookies. Running `pixel-worker onboard` initiates a 15-minute Device Code (`PCT-XXXX-XX`) and opens `/onboard?code=...` so the user explicitly reviews permissions and approves binding. Admins may also enable `strictDeviceReview` to manually vet new devices.

## 3. Proof of First Spark (POFS): Cryptographic Idea Provenance

Implemented in `src/server/provenance.mjs`, protocol **`PCT-POFS-v1`** ensures every original concept receives tamper-evident cryptographic attribution.

### 3.1 Tamper-Evident SHA-256 Hash Chain

When proposal `P_i` is created, the engine assigns a strictly monotonic `provenanceIndex` (`i`), `originatorId`, UTC ISO-8601 `originatedAt`, and links to the previous record's `prevIdeaHash` (`H_{i-1}`, starting from 64-zero `GENESIS_HASH`):

```text
C_i = JSON.stringify({
  protocol: "PCT-POFS-v1",
  name, tagline, description,
  originatorId, originatedAt,
  prevIdeaHash: H_{i-1}
})

H_i = SHA-256_hex(UTF-8(C_i))   // 64-char lowercase hex fingerprint
```

Any retroactive mutation of a historical title, tagline, originator, or timestamp invalidates the chain check (`verifyProvenanceChain().valid === false`). Existing hashes are never silently overwritten on restart.

### 3.2 Bilingual Anti-Copycat Similarity Guard

To detect cross-language clones, field shuffling, or stripped descriptions, the engine runs **Unicode NFKC normalization + bilingual tokenization + multi-field max Jaccard similarity**:

1. **Feature Set `T(s)`**: Lowercase alphanumeric words (`en:<word>`) plus adjacent CJK character bigrams (`zh:<c_k c_{k+1}>`).
2. **Max Cross-Field Score**: `S_final = max(J_name, J_tagline, J_desc, J_matched, J_all) ∈ [0, 1]`.
3. **Two-Tier Enforcement**:
   - **Warning (`S_final >= 0.40`)**: Real-time UI warning surfacing the original originator and allowing explicit derivative attribution (`inspiredByHash`).
   - **Hard Block (`S_final >= 0.65`)**: Server rejects duplicate proposals with HTTP **`409 POTENTIAL_COPYCAT`**, displaying the original creator, UTC timestamp, and SHA-256 hash while offering a 1-click **`POST /api/projects/:id/join`** button to co-build the original idea instead of cloning it.

### 3.3 Public Cryptographic Verification & PNG Certificates

- **Public Verification Page**: Anyone—without logging in—can open `GET /verify/:hash` (supporting full 64-char hashes or 8+ char prefixes) to inspect the **`✅ VERIFIED ON PIXELCOMPUTE PROVENANCE CHAIN`** seal. Forged hashes return HTTP `404`.
- **Downloadable Idea Certificate**: Players can export a 900×520 pixel-art *Proof of First Spark Certificate PNG* displaying the originator, UTC timestamp, full SHA-256 fingerprint, and revenue split.

## 4. The 5% / 85% / 10% Merit Split & 70/30 Anti-Dilution Mathematics

Our core economic ethic is simple: **Honor the first spark permanently, never allow passive squatting, reward builders strictly in proportion to verified work, and mathematically protect core engineers from micro-task spam.**

### 4.1 Top-Level Revenue Allocation (5% / 85% / 10%)

For any launched project receiving gross revenue `R > 0` (USD):

```text
R_spark    = round2(0.05 × R)                      // 5% Permanent Originator Spark Royalty
R_platform = round2(0.10 × R)                      // 10% Platform Provenance & Ops Carry
R_merit    = round2(R - R_spark - R_platform)      // 85% Builders Merit Pool
```

- **5% Spark Royalty (`R_spark`)**: Permanently credited to the chain-verified `originatorId`, even if they write zero lines of code.
- **85% Merit Pool (`R_merit`)**: Distributed strictly by verified Proof of Accepted Work (PoAW) under the 70/30 bucket rule. If the originator also builds, they earn **both** their 5% Spark Royalty **plus** their earned share of the 85% pool.
- **10% Platform Carry (`R_platform`)**: Sustains provenance verification, review infrastructure, and payment rails.

### 4.2 Inside the 85% Merit Pool: The 70/30 Anti-Dilution Invariant

Every accepted task is assigned to one of two mutually exclusive buckets (`src/server/governance.mjs`):

- **🔥 Core Bucket (`core`)**: Guild bounties, `feature_pr`, `architecture`, `bugfix`, and peer-review approval points (`+5`). Cap: **70%** of the Merit Pool (**59.5%** of gross revenue).
- **⚙️ Peripheral Bucket (`peripheral`)**: API micro-tasks, `i18n`, `docs`, `pixel_spec`, `unit_test`, `qa_audit`. Cap: **30%** of the Merit Pool (**25.5%** of gross revenue).

Let `C_total` be total core points and `P_total` be total peripheral points:

```text
If C_total > 0 and P_total > 0:  M_core = round2(0.70 × R_merit),  M_periph = round2(R_merit - M_core)
If C_total > 0 and P_total = 0:  M_core = R_merit,                 M_periph = 0
If C_total = 0 and P_total > 0:  M_core = 0,                       M_periph = R_merit

Contributor u total payout:
D_u = I(u == originator) × R_spark + M_core × (c_u / C_total) + M_periph × (p_u / P_total)
```

**Anti-Dilution Invariant**: Whenever `C_total > 0`, even as `P_total → ∞`, every core engineer's minimum share is mathematically locked at `0.595 × R × (c_u / C_total)`, reconciled to exact `$0.01` precision with zero floating-point drift.

## 5. 4-Layer Anti-Slop Governance Moat

To make submitting low-effort AI garbage have strictly **negative expected value**, every submission passes through four layers:

1. **Layer 1 — Fixed Task Quotas & Machine PoAW Gates (`src/server/verifier.mjs`)**: Points are fixed per task (never per line or token). Automated checks block short fluff, repetitive slop, low lexical diversity, invalid JSON, and malformed PR links.
2. **Layer 2 — Cross-Model AI Blind Review (`runAiBlindReview`)**: Computes `diffLinesAdded/Removed`, `bloatRatioPct` (flagging duplicate lines, excessive comments, empty stubs, placeholder comments, and bloated add-only diffs), `aiScore` (5–99), and Low/Medium/High risk badges.
3. **Layer 3 — Merit-Weighted Peer Review Queue (`canUserReview`)**: Only verified project contributors, originators, and admins can approve or reject queued submissions (unqualified accounts receive HTTP `403`). Approving clean PRs rewards reviewers **`+15G` + `+5` core points + `+1` reputation**.
4. **Layer 4 — Staking, Slashing & Cooldowns**: Core bounties require Reputation ≥ 60 and freeze **`25G–30G`** stake gold. Accepted work refunds 100% of stake; rejected AI slop **slashes the entire stake directly to the reviewer as a bug-catching bounty**, deducts `-5` reputation, and triggers an HTTP **`429 WORKER_COOLDOWN`** lockout after 2 strikes.

## 6. Non-Custodial 3-in-1 Settlement & Stablecoin Micropayments

### 6.1 Zero Native Token Policy (1:1 USDC / USDT Only)

Speculative project tokens corrupt developer incentives into price speculation. PixelCompute Town commits to a strict **Zero Native Token Policy**:
- All bounties, ads, Pro passes, and dividends are denominated in **USD** and settled on-chain solely in **1:1 USDC or USDT**.
- Native support for **Base** (recommended, `< $0.01` gas), **Polygon**, **Arbitrum**, and **Solana** makes global micro-dividends down to **`$5.00 USD`** instant and economical—eliminating `$25–$40` wire fees and regional banking barriers.
- Strictly **non-custodial**: the platform never holds user private keys, enforces 30-minute order windows with unique memo codes (`PCT-XXXXXX`), and blocks `TxHash` replay (`HTTP 409`).

### 6.2 Tri-Rail Payment Engine (`src/server/payments.mjs`)
1. **Stablecoins**: 4-chain USDC / USDT pay-in and `$5+` wallet payout withdrawals.
2. **Fiat Checkout**: **Polar.sh** (Merchant of Record with automated global tax handling) & **Stripe**, with HMAC-SHA256 webhook verification.
3. **Redeem Codes**: Admin batch code generator (`PIXEL-PRO-XXXX`) for frictionless sales via Afdian, Ko-fi, or Gumroad.
