## 1. 时代痛点：AI 经济的三重结构性失衡

### 1.1 每月归零的闲置算力黑洞

AI 基础设施的计费模式正分化为“按量 API 赠金／免费配额”与“固定月／周费率的官方 CLI／IDE 订阅（如 Gemini CLI、Claude Code、Codex CLI、Cursor）”。多数开发者在平峰期仅消耗不到 30%–50% 的可用额度，剩余配额在结算周期结束后立即归零。另一方面，市面上试图“回收”闲置额度的黑灰产共享反代池，往往通过非法收集用户 Cookie、OAuth Token 或转售 API Key 运作，不仅严重侵害隐私，更直接违反主流 AI 厂商的服务条款（ToS），导致开发者账号遭永久封禁。

### 1.2 原创点子被低成本复制与“蒸馏”

在传统软件工程时期，从构想到最小可行产品（MVP）需要数月人力，因此点子本身较难被瞬间掠夺；然而在 AI 辅助编程时代，一个精准切中痛点的创意只需公开片刻，便可能被他人用 AI 批量复制、微调包装并抢先发布。若协作平台无法提供不可篡改的首发时间戳公证与反抄袭拦截机制，原创发起人将失去分享灵感的动机；反之，若平台过度向“只提想法不动手”的发起人倾斜（例如让发起人拿走 50% 以上永久份额），又会吓跑真正投入时间与算力把产品落地交付的实干工程师。

### 1.3 垃圾 AI（AI Slop）稀释开源实干者

开源维护者近年普遍遭遇“低品质 AI PR 洪水”：自动化脚本使用极低成本模型大量提交无意义的 README 改字、重复注释、空函数占位或冗长灌水 Diff。在传统“按提交次数”或“按消耗 Token 数”计酬的激励模型中，这类垃圾产出不仅浪费维护者的审阅精力，更会严重稀释核心开发者的贡献权重，造成“劣币驱逐良币”的系统性崩坏。

### 2.1 Zero-Trust BYOK（Bring Your Own Key）
- 适用轨道：**自动工坊 (`api_auto`)**。
- 所有推理请求直接由客户端浏览器发往目标模型端点（Google `generativelanguage.googleapis.com`、OpenRouter、DeepSeek 或本机 `http://localhost:11434/v1`）。
- API Key 仅存储于浏览器端 `localStorage`（键名 `pixel_compute_town_byok_v1`），任何 HTTP API 请求都不会夹带用户密钥回传至平台服务器。
- 内置单次任务最大输出 Token 上限（默认 `2,048`，可调 `256`–`16,384`）与每日小人 Token 体力软上限，避免自动化挂机失控超支。

### 2.2 Compliant BYOT（Bring Your Own Tool）与 Device Flow 核准
- 适用轨道：**悬赏工会 (`guild_bounty`)**。
- 针对月／周订阅工具，平台提供单一零依赖本机桥接器 `bin/pixel-worker.mjs`（约 1,180 行纯 Node.js 源码，公开可审计）。
- **严格隔离边界**：`pixel-worker` 不读取 `~/.gemini`、`~/.claude`、`~/.codex` 或任何浏览器 Cookie，仅在用户本机通过 `child_process` 调用用户自己核准的官方 CLI 指令，并于提交前由开发者亲自确认。
- **设备注册与严格审核**：执行 `pixel-worker onboard` 会产生 15 分钟有效之设备授权码（`PCT-XXXX-XX`）并导向浏览器 `/onboard?code=...` 页，由用户检视 4 条零信任权限清单后手动核准；若运营镇长开启“严格设备审核模式（`strictDeviceReview`）”，新设备将进入 `pending_review` 队列，经人工核准才可正式上线。

## 3. Proof of First Spark（POFS）创意溯源协议

为落实“尊重原创首发、反对抄袭蒸馏”的价值主张，PixelCompute Town 在 `src/server/provenance.mjs` 实现了零依赖密码学存证协议 **`PCT-POFS-v1`**。

### 3.1 SHA-256 不可篡改创意哈希链

每一笔新提案 `P_i` 在创建瞬间，系统依序指派单调递增索引 `i`（`provenanceIndex`）、首发者账号 ID（`originatorId`）、UTC ISO-8601 时间戳（`originatedAt`）与前一笔创意的指纹 `H_{i-1}`（创世前序哈希为 64 个 `0`，即 `GENESIS_HASH`）。其不可篡改指纹 `H_i` 定义如下：

```text
C_i = JSON.stringify({
  protocol: "PCT-POFS-v1",
  name, tagline, description,
  originatorId, originatedAt,
  prevIdeaHash: H_{i-1}
})

H_i = SHA-256_hex(UTF-8(C_i))   // 64 位小写十六进制指纹
```

任何对历史项目名称、简介、首发者或时间戳的篡改，都会导致该区块及所有后续区块的 `verifyProvenanceChain()` 验证失败（`valid === false`），且平台启动加载时绝不自动覆写既有 `ideaHash`，完整保留防篡改审计能力。

### 3.2 中英双语反抄袭算法

为防范中英文混合改写、跨字段粘贴或省略简介来规避查重，系统采用 **NFKC 正规化 ＋ 双语特征切分 ＋ 多维度最大 Jaccard 相似度**：

1. **双语特征集 `T(s)`**：
   - 英文／数字词元：提取小写 `[a-z0-9]+` 标记为 `en:<word>`。
   - 中日韩（CJK）字符序列：长度 ≥ 2 时提取所有相邻 **2-gram** 标记为 `zh:<c_k c_{k+1}>`（单字则标记 `zh:<c>`）。
2. **Jaccard 相似度**：`J(A, B) = |T(A) ∩ T(B)| / |T(A) ∪ T(B)| ∈ [0, 1]`。
3. **跨字段防稀释取最大值**：对候选提案与每笔既有原创分别计算名称、副标、简介、对齐字段合并与全字段合并相似度，取最大值 `S_final = max(s_name, s_tagline, s_desc, s_matched, s_all)`。
4. **双门槛治理动作**：
   - **警示门槛（`S_final >= 0.40`，`COPYCAT_WARN_THRESHOLD`）**：前端即时弹出相似创意警示，要求创作者确认差异化并标记致敬来源指纹（`inspiredByHash`）。
   - **拦截门槛（`S_final >= 0.65`，`COPYCAT_HIGH_THRESHOLD`）**：后端硬性拒绝创建重复提案，返回 HTTP **`409 POTENTIAL_COPYCAT`**，附上原创首发者、时间戳与 `ideaHash`，并引导调用 `POST /api/projects/:id/join` 直接加入原创意共建。

### 3.3 无门槛公开查验与凭证输出

- **公开 API**：`GET /api/provenance/chain`（逐笔重算整条哈希链）与 `GET /api/provenance/verify/:hash`（支持完整 64 位或 8+ 位前缀）。
- **公开 SSR 查验页**：任何人免登录访问 `GET /verify/:hash`，通过即亮出 **`✅ VERIFIED ON PIXELCOMPUTE PROVENANCE CHAIN`** 官方印章；伪造或篡改返回 HTTP `404` 红牌警告。
- **像素公证证书**：前端可即时绘制并下载 900×520《创意首发溯源证书 PNG》，内嵌首发者、UTC 时间戳与 64 位指纹供外部社区与版权归档。

## 4. 5% / 95% / 0% 零抽成动态分红与 70/30 防稀释数学模型

PixelCompute Town 的分配哲学可浓缩为一句话：**“尊重踏出 0 到 1 的创意火花，平台一分钱都不抽；让真正把产品交付上线的实干者瓜分整整 95%，并用数学锁死防稀释护城河。”**

### 4.1 顶层分配公式（5% / 95% / 0%）

设某已上线项目在结算周期获得总营收 `R > 0`（单位：USD），系统将 100% 营收全数归还创作者与共建者：

```text
R_spark    = round2(0.05 × R)                      // 5% 首发创意永久版税
R_platform = $0.00 (0%)                            // 0% 平台抽成（100% 全免靠打赏）
R_merit    = round2(R - R_spark) = 0.95 × R        // 95% 实干建设多劳多得池
```

- **`R_spark`（5% 首发创意永久版税）**：无条件、永久归属链上记录的 `originatorId`。
- **`R_merit`（95% 实干建设多劳多得池）**：依 70/30 分桶隔离规则分配给所有通过 PoAW 验收的实干贡献者。若发起人亲自参与实现，其领取金额为 `R_spark` 与实干池所得的**直接叠加**。
- **`R_platform`（0% 平台抽成）**：平台坚持永久全免，不抽成任何孵化营收与现金悬赏，仅接受社区自愿打赏维持服务器运转。

### 4.2 95% 实干池内部：70/30 分桶隔离数学证明

为防堵廉价 AI 狂刷周边微任务稀释核心开发者，系统在 `src/server/governance.mjs` 将每笔验收通过的贡献点数严格归入两个互斥分桶：

- **🔥 核心实干桶（`core`）**：涵盖工会悬赏大单、`feature_pr`、`architecture`、`bugfix` 以及资深审阅人的 `+5` 核心审阅奖励点。配额上限 **70%**（占总营收 **66.5%**）。
- **⚙️ 周边微任务桶（`peripheral`）**：涵盖 API 轨道微任务、`i18n`、`docs`、`pixel_spec`、`unit_test`、`qa_audit`。配额上限 **30%**（占总营收 **28.5%**）。

设全体参与者在核心桶的总点数为 `C_total`，在周边桶的总点数为 `P_total`，则双桶实际分红池 `(M_core, M_periph)` 定义为：

```text
若 C_total > 0 且 P_total > 0：M_core = round2(0.70 × R_merit),  M_periph = round2(R_merit - M_core)
若 C_total > 0 且 P_total = 0：M_core = R_merit,                 M_periph = 0
若 C_total = 0 且 P_total > 0：M_core = 0,                       M_periph = R_merit

贡献者 u 的最终分红：
D_u = I(u == originator) × R_spark + M_core × (c_u / C_total) + M_periph × (p_u / P_total)
```

**防稀释不变式（Anti-Dilution Invariant）**：只要 `C_total > 0`，无论周边桶总点数 `P_total → ∞`，核心实干者 `u` 的核心池收益下界永远锁死在 `0.665 × R × (c_u / C_total)`，零浮点残差（精确至 `$0.01`）。

## 5. 4 层防垃圾 AI 治理体系（Anti-Slop 4-Layer Moat）

除了数学上的 70/30 分桶，PixelCompute Town 在任务全生命周期建立 4 道串联防线，让制造垃圾 AI 提交的**期望回报恒为负值**：

### Layer 1：任务定额 ＋ 70/30 分桶隔离 ＋ PoAW 机器硬门槛
- 每张任务的贡献点数皆为固定定额（而非按字数或 Token 计算），彻底断绝“写越长领越多”的动机。
- 所有提交先通过 `src/server/verifier.mjs` 的三项硬校验：最小实质长度门槛、AI Slop 反灌水侦测（封锁重复字符、英文词汇多样性 `< 22%`、中文 2-gram 多样性 `< 28%`、多行复制粘贴 `< 35%`、占位符关键字）、以及依任务类别检查合法 JSON／代码特征／GitHub PR 格式。

### Layer 2：跨模型 AI 盲审体检（`runAiBlindReview`）
- 进入审阅队列的提交立即接受自动化盲审诊断，解析 Unified Diff 或代码正文，产出 `diffLinesAdded`、`diffLinesRemoved`、**注水比 `bloatRatioPct`（0–100%）** 与 **盲审分数 `aiScore`（5–99）** 及红黄绿三级风险灯号（侦测重复行、过高注释占比、空函数占位符与异常纯新增大 Diff）。

### Layer 3：资深实干审阅团（4 阶实力认证）与合并否决权
- 支持开发者主动勾选送审，或由镇长开启全局强制双阶段实干审阅（`settings.peerReviewRequired = true`）。
- **严格实力分级（`evaluateReviewerEligibility`）**：硬性禁止自己审自己（HTTP `403 SELF_REVIEW_FORBIDDEN`）。仅限创始镇长、镇长特聘资深评委（`verifiedReviewer`）、项目首发者，以及通过真实核心代码交付验证的 **项目实战核心工程师**（项目核心点 `>= 50` 且信誉 `>= 80`）或 **全镇认证资深工程师**（累计核心点 `>= 150` ＋ `>= 2` 笔核心单 ＋ 信誉 `>= 85`；仅刷周边翻译／文档永不获审阅权）具备裁决资格。
- **正向审阅激励**：批准优质 PR，审阅人实得 **`+15G` 金币 ＋ `+5` 核心池贡献点 ＋ 信誉 `+1`**。

### Layer 4：诚意押金没收 ＋ 接单限时自动释放（防占坑）＋ 信誉冷却惩罚
- **信誉门槛**：承接工会核心大单默认须达 **信誉分 ≥ 60**（不足拦截 HTTP `403 REPUTATION_TOO_LOW`）。
- **诚意押金（Stake Gold）**：领取工会大单冻结 **`25G`**（高价现金悬赏 ≥ `$25` 冻结 **`30G`**）。通过验收或主动 `release` 则 **100% 退还**；一旦被实干审阅团驳回，**全额押金立即没收并直接赔付给该名审阅人**作为抓虫赏金！
- **接单超时自动解除机制（防占坑摆烂）**：API 微任务认领租约默认 **30 分钟**、工会核心悬赏默认 **24 小时**。超时未交付系统后台自动回收任务重回开放池，同时扣除 **50% 押金**与信誉 **`-3`**；提前主动点击“放弃”则 100% 退押金、零惩罚。
- **累计违规冷却**：垃圾提交者同时扣除信誉分 **`-5`**；同一算力小人连续累计 **`2` 次垃圾提交（`SLOP_STRIKE_LIMIT = 2`）**，立即锁定反刷冷却期（默认 **`60` 秒**），冷却期间接单返回 HTTP **`429 WORKER_COOLDOWN`**。

## 6. 非托管稳定币出款与自愿打赏支持基础设施

### 6.1 为何只用 1:1 USDC / USDT，而绝不发行平台空气币？

大量 Web3 协作项目失败的根本原因，在于发行缺乏真实需求支撑的原生波动代币（空气币），导致项目从“做产品”沦为“炒币与倒货”。PixelCompute Town 明确宣示 **Zero Native Token Policy（零原生代币原则）**：

1. **计价与结算锚定真实购买力**：所有现金悬赏与项目分红均以 **USD** 计价，链上只接受全球流通、1:1 美元储备锚定的 **USDC 与 USDT**。
2. **多链低 Gas 微支付**：原生支持 **Base（推荐，手续费常低于 `$0.01`）**、**Polygon**、**Arbitrum** 与 **Solana**，让门槛低至 **`$5.00 USD`** 的跨国开发者分红微支付变得经济可行，不受传统银行跨境电汇高昂手续费与地区开户限制阻碍。
3. **非托管与防重放安全**：平台不为用户代管私钥，仅绑定用户个人收款地址；所有打赏与出款记录具备唯一备注码（`PCT-XXXXXX`），且对链上 `TxHash` 进行严格格式验证与全库防重放去重（重复使用返回 `409`）。

### 6.2 自愿打赏双轨支持通道

平台全功能免费开放，仅在创作者与开发者觉得好用时提供完全自愿的随喜打赏入口（`src/server/payments.mjs`）：
